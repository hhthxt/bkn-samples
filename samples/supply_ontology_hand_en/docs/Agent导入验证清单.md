# Agent 导入验证清单

> 适用：把 `samples/supply_ontology_hand` 导入**真实 OpenBKN 环境**后，由实施同学或智能体按本清单验收动态能力。  
> 灌库 / 扫描 / 绑定步骤仍以 [openbkn-hand-import-guide_cn.md](./openbkn-hand-import-guide_cn.md) 为准。  
> 能力与题目：[动态能力设计](./场景驱动的供应链动态能力设计.md) · [口径清单](./能力口径清单.md) · [业务问答测试集](./业务问答测试集.md)

## 0. 智能体被要求「导入并验证」时的工作顺序

不要一上来就做齐套。按下面顺序，每步留下证据（命令输出、查询 JSON、问答记录）。

```text
A. 平台就绪（说明书 §1）
B. 导入知识网络 JSON（步骤 2）→ 确认 id=supply_ontology_hand
C. 灌入 data/*.csv（步骤 3）→ 行数与下表一致
D. Catalog 扫描 + 对象绑定（步骤 4～5）→ 11 个 bind:true 可查
E. smoke_test.py 通过
F. 动力层：python3 tools/power_layer.py all --kn-id supply_ontology_hand
   （创建指标 + 挂逻辑属性 + 快照验收）
G. 注册并发布场景技能（至少 S1）
H. 跑业务问答测试集（先 S4 规模，再 S1 倒排）
I. 治理题：监控任务须确认；发起 PO 拒绝自动
```

改的是 `tools/config.yaml`（库地址、Catalog 名），**不要改** CSV 文件名、`object_table_map.yaml`、`kn_id`。

## 6. 给智能体的最短系统提示（可粘贴）

```text
你正在使用知识网络 supply_ontology_hand（供应链本体知识网络-手工版）。
数据是体验包脱敏样例：30 个成品，仓库用苏州/乌鲁木齐/哈尔滨，不要用昆山/新疆，不要用另一张网的 431。

生产齐套默认只加这 7 个仓的可用库存：苏州半成品仓、苏州成品仓、苏州电子原料仓、苏州无人机原料仓、苏州装配原料仓、乌鲁木齐成品仓、哈尔滨成品仓。
成品发货看：苏州成品仓、乌鲁木齐成品仓、哈尔滨成品仓。

问规模/库存/预测 → 用已建模指标。不要把可售、齐套是否通过、延迟天数做成指标。
问某日能否齐套 → 技能：生产计划倒排。标杆：382-000005 + 2026-05-14。无截止日/无预测不定论。净需求在途只计未关闭 PO。10 档只在 S1 内用。
问现在最多能卖多少 → 可售技能，先确认替代。合计可售=成品库存+理论可产，不加在途，不是交期承诺。替代组内 MAX。
问还能做多少 / 现有料能组装多少 → 理论可产（二者 P0 同一结果），不要再减成品库存，不要当成可售。
问要 X 套齐不齐且没给日期 → 净需求函数，不是 S1。
问多单新需求能不能接 → 覆盖分析技能（共享池含在途）。
问 BOM 清单 / 有多少子件 → 一类 BOM 清单（数量是出参，不建指标）。
问几款（≥2）BOM 上有哪些相同的料（数量未定）→ 一类「产品 BOM 共用清单」，全部产品同时交；不要开 S3/争用。
问各层子件有多少 / 有没有替代 → 停在一类函数。
建监测任务 → 先给参数，用户确认再执行。
下采购订单 → 禁止自动执行。
已建模指标禁止用 SQL 重算。口径必须回显。理论可产 ≠ 合计可售 ≠ 齐套净需求。
```
