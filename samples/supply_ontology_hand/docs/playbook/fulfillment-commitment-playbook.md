# 业务故事 Playbook：客户需求承诺前的供应链履约核查

## 故事

客户希望在 2026-05-31 前交付 3000 台 `U00-000080`。计划负责人不能只看成品库存：需要把产品 BOM、物料库存、在途 PO、未清 PR、MRP、标准交期和生产周期串成一份可解释结论。

## 一次完整体验

### 第一步：选定需求预测

使用 `forecast_id=0000023181`、产品 `U00-000080`、数量 3000、截止日 2026-05-31。数量必须与预测单一致，不一致时应停止并提示。

### 第二步：S1 倒排与齐套

调用 `backward_plan`。观察：

- 产品层和子件层的日历日时间窗；
- 可用库存与未清 PO 在途；
- 物料缺口和供应状态；
- A/B 延迟与最大延迟；
- `can_deliver_on_time`。

本样例金标显示最大延迟 166 天，因此不能直接向客户承诺按期交付。

### 第三步：S2 可售能力

调用 `total_sellable`，区分成品仓库存和理论可产。样例结果为 20，不能把“理论可产”“合计可售”“要 X 套齐套”混为一个口径。

### 第四步：S3 新需求覆盖（可选）

当存在第二张需求时，调用共享物料争用能力，按显式需求顺序扣减库存 + 在途，输出每张需求的满足状态和共享物料证据。

### 第五步：形成行动提案

S1 有缺口或延迟时，报告只提出：

- 创建生产计划监控任务；
- 创建采购决策记录。

两者都是 `proposed`，不是已经执行的 ERP 动作。

### 第六步：人工批准后 dry-run

批准凭证绑定提案摘要、Action 类型、Interaction、批准人、有效期和幂等键。重复提交必须拒绝；任务粒度固定为一个产品 + 一张预测单；物料明细只是履约证据。

### 第七步：回读与复盘

读取任务状态、证据明细、`snapshot_id` 和 `interaction_id`。修改样例库存或交期后重跑，比较瓶颈是否发生变化；不要删除历史证据。

## 在线迁移

先完成离线体验，再按 [OpenBKN 在线体验](../quickstart/online-openbkn.md) 将数据来源替换为第三方 Agent 的官方 Context Loader 查询。函数合同和报告不变。
